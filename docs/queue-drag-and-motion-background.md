# 0.9.5：队列拖动重做与动态背景

这一版解决播放列表拖动的两个实际毛病，并把背景从静态图扩展到视频与动图。

## 一、去掉行首拖动把手

队列面板（点底部三条横线打开）每行原来左侧有一个 `DragHandle` 图标 —— 两道横线，既占宽度又和右上角菜单图标容易混。现在整行只保留：序号圆标、标题/作者/时长、圆形播放键、移除键。

拖动改为只走**长按整行**：`detectDragGesturesAfterLongPress` 挂在 `LazyColumn` 上，长按命中哪一行就从哪一行开始拖。可点面积比原来的 28dp 把手大得多，误触反而更少。代价是没有可见的拖动提示，靠长按震动反馈确认。

## 二、两个拖动 Bug 的原因与修法

### Bug 1：第一个条目往下拖会抖

旧逻辑：被拖行中心进入**任意**其他行的边界就立即换位。换位之后布局重排，被拖行的槽位下移一格，中心点随即又落回原来那行的槽位里 —— 于是又换回去，形成来回跳。

修法是把判定从「碰撞」改成「越过中线」：

```kotlin
val crossed = if (to > from) center > target.offset + target.size / 2f
              else center < target.offset + target.size / 2f
if (!crossed) return
```

只有中心越过目标行的中线才换位。换位后中心正好停在新位置的中心附近，不会再次满足条件，抖动消失。

### Bug 2：拖到看不见的位置就停止重排

旧逻辑的自动滚动只做了 `scrollBy`，没有处理两件事：

1. **滚动后中心点没跟着走**。列表向上滚了 20px，所有行的布局 offset 都减 20，而被拖行的视觉中心还在原处，于是中心相对内容「漂移」了，落点判定越来越偏。
2. **中心拖出视口后没有任何行包含它**。`firstOrNull { center in it }` 返回 null，`moveAtCenter()` 直接 return —— 列表还在滚，顺序却不动了。

修法：

- `scrollBy` 返回实际消费的滚动量，把它加到 `center` 上，保证被拖行始终贴在手指下面；
- 命中不到行时，取**离中心最近的边缘行**作为落点。中心在视口下方就落到最后一个可见行，继续滚就继续往下挪；
- 自动滚动循环里每帧都重新跑一次 `moveAtCenter()`，不再只依赖手指新产生的拖动事件。滚到列表尽头自然停止。
- 边缘区从 48dp 开始，速度上限从 14 提到 18（每帧像素），长列表拖到底更快。

### 已知边界

- 快速甩动时 Compose 的拖动事件按帧合并，极端速度下仍可能少换一格，松手后再补一次即可。
- 顺序保存失败会提示「排序未保存，请重试」，并把草稿恢复成服务器/播放器里的真实顺序，不会留下假的界面顺序。

## 三、动态背景（视频 / 动图）

### 支持的来源

| 类型 | 格式 | 实现 |
|---|---|---|
| 视频 | mp4 / webm（H.264/VP9 等系统解码器支持的编码） | 独立 `ExoPlayer` + `PlayerView`，静音、单曲循环、`RESIZE_MODE_ZOOM` 铺满裁切 |
| 动图 | GIF / WebP | API 28+ 用 `ImageDecoder` + `AnimatedImageDrawable` 无限循环；API 26/27 用 `Movie` 解 GIF |

选中的地址通过 `OpenDocument` 拿持久化读权限，重启后仍可读。一次只生效一个背景：选动态背景会清掉静态图，选静态图/内置图会清掉动态背景。

### 不干扰正在播放的视频

- 视频播放器是**独立实例**，和播放正片的 `PlayerHolder` 无关；
- `volume = 0`，且 `setAudioAttributes(..., handleAudioFocus = false)`，不申请音频焦点，不会把正片声音压低或暂停；
- 跟随 Activity 生命周期：`ON_STOP` 暂停、`ON_START` 继续，后台不空转。

GL 合成、解码耗电与发热是真机要看的点：长视频、高码率壁纸比静态图明显费电，建议用 10–30 秒循环片段。

### Wallpaper Engine 壁纸怎么用

Steam 的壁纸引擎把订阅内容放在 `steamapps/workshop/content/431960/<id>/`：

- **视频类壁纸**：目录里直接有 `.mp4`（少数是 `.webm`）。把这个文件传到手机，在「我的 → 外观 → 选择背景视频」里选中即可，不需要转码。
- **场景 / 网页类壁纸**：`scene.pkg` 是打包格式，手机端没有解析器，读不了。需要先在电脑上让壁纸引擎把场景导出/录制为视频（或用社区工具转换），得到 mp4 后再选。
- **动态壁纸的工程目录**（含 `project.json`）不是视频，不能直接选。

App 不联网、不读取 Steam 目录，也不解析 pkg，只接受系统文件选择器给出的单个视频/动图文件。
